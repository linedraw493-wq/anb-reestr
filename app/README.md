# Реестр блогеров — код

Проект Ассоциации блогеров. Решения лежат в `../voprosy-i-dyry.md`, что
сделано и что осталось — в `../SOSTOYANIE.md`, сверка со спекой заказчика —

## Как устроено

**Одна служба.** FastAPI сам отдаёт собранные страницы: один адрес, один
деплой, и не надо возиться с разрешениями между доменами.

| Папка | Что это |
|---|---|
| `web/` | экраны: Vite + React 19 + TypeScript |
| `api/` | сервер: FastAPI + asyncpg + PostgreSQL, миграции накатываются сами |
| `tools/` | подъём стенда, перенос таблицы заказчика, наполнение каталога |

Стек взят у «Лидера» (`C:/leader/`) — он в доме уже отработан.

## Поднять стенд

```bash
bash tools/podnyat.sh     # база, сервер, экраны
bash tools/opustit.sh     # остановить
```

Экраны — `http://localhost:5173`, сервер — `http://127.0.0.1:8000`. При
разработке экраны идут через vite, а `/api` он проксирует на сервер.
Собранный сайт (`npx vite build --prefix web`) отдаёт сам сервер по 8000.

## Бой: Vercel + Neon

Живой сайт — **https://anb-reestr.vercel.app**. Выкат из этой папки:

```bash
npx vercel deploy --prod --yes     # из app/, не из web/
```

Как это собрано (`vercel.json`):

- **экраны** — `@vercel/static-build` из `web/package.json`; Vercel кладёт
  собранное не в корень, а в `/web`, поэтому в `routes` две отдельные строки
  на `/assets` и на возврат `/web/index.html`. Без них главная отвечала 404;
- **сервер** — `@vercel/python` из `api/index.py`; там нет своего кода, только
  дорога к `app.main`;
- всё, что не `/api` и не найдено файлом, отдаётся как `index.html` — это
  обычная одностраничная разводка;
- `X-Robots-Tag: noindex` — стенд с живыми людьми поисковикам не отдаём.

**База на бою — Neon**, бесплатный тариф, адрес в `.env` под именем
`NEON_DATABASE_URL`. Миграции накатываются сами при первом запросе.
Инструменты умеют ходить туда же: `DATABASE_URL=... py app/tools/…`.

Две ловушки, на которых уже споткнулись 02.09.2026:

1. **`.vercelignore` без косой черты в начале** ловит файлы на любом уровне:
   `.env.*` съел `web/.env.production`, и сайт собрался на заглушке — каталог
   живой, а вход и карточка выдуманные. Правильно `/.env.*`. Для верности
   `VITE_API` и `VITE_OTP` теперь заданы ещё и в настройках Vercel.
2. **Neon за посредником** (адрес с `-pooler`): asyncpg обязан работать с
   `statement_cache_size=0`, иначе сервер падает с «prepared statement
   already exists».

Переменные окружения на бою: `DATABASE_URL`, `OTP_SECRET`,
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CODE_CHAT_ID`, `VITE_API`, `VITE_OTP`.
Заведены на Production; **предпросмотрам они не видны** — поэтому пробный
выкат без `--prod` падает на базе, это не поломка.

## Выключатели

| Выключатель | Где | Значения | Что решает |
|---|---|---|---|
| `VITE_API` | `web/.env.local`, `web/.env.production` | `fake` · `live` | сервер или заглушка в браузере |
| `VITE_OTP` | там же | `fake` · `live` | код `000000` или настоящий |
| `MASTER_KOD` | окружение сервера | пусто · `111111` | демо-вход: этот код подходит любому, коды никуда не шлются |
| `ADMIN_TELEFONY` | окружение сервера | пусто · телефоны через запятую | кому ещё дать админку, кроме владельца |
| `ADMIN_LOGIN` · `ADMIN_PAROL` | окружение сервера | пусто · `admin` / `admin` | вход в админку по логину и паролю (рядом с телефоном+кодом) |
| `MODERATSIYA` | окружение сервера | `0` · `1` | карточка идёт в каталог сразу или через модератора |
| `COOKIE_SECURE` | окружение сервера | `0` · `1` | локально `0`, на бою `1` |

На бою обе сборки стоят на `live`. До 02.09.2026 в `web/.env.production`
было `VITE_API=fake` — от времён заглушки на Vercel; с такой сборкой сайт
на бою работал бы на выдуманных данных.

## Коды входа через Telegram

Временная замена SMS-оператору, слово владельца 02.09.2026. Бот
**@Kikokpklkbot**, все коды падают **в один чат владельца** — он их и
раздаёт. Иначе нельзя: бот Telegram не умеет писать первым ни по нику, ни
по номеру, только тому, кто сам ему написал.

Кода нигде не хранится — в базе лежит его отпечаток. Пять минут жизни,
пять попыток, счёт попыток в базе. Появится оператор — меняется один файл
`api/app/telegram.py`.

Отдельно есть **резервный код**: админ выдаёт его в
`/moderator/priglasheniya`, читает с экрана и передаёт голосом. Это то, что
спека называет «коды выдаёт администратор через админку».

## Демо-вход и админка для клиента

Слово владельца 03.09.2026: клиенту (Ассоциация) нужно самому зайти в
админку и рассылать инвайты, пока нет казахстанского SMS-оператора.

- **`MASTER_KOD`** (по умолчанию `111111`) — на экране входа этот код
  подходит **любому**, настоящие коды никуда не отправляются: Telegram и
  SMS для входа не нужны. Экран ждёт шесть цифр. Так же входят и блогеры
  по своим ссылкам-приглашениям.
- **`ADMIN_TELEFONY`** — телефон(ы) клиента через запятую: при старте
  сервера они заводятся в базе с ролью `admin`. Клиент входит по своему
  номеру и коду `111111`, дальше — кнопка «Админка» → «Приглашения».
- **`ADMIN_LOGIN` / `ADMIN_PAROL`** (по умолчанию `admin` / `admin`) — на
  экране `/vhod` под чертой есть «Вход для администратора»: логин и пароль
  вместо телефона. За ними один общий admin-кабинет без телефона. Клиенту
  можно дать просто `admin` / `admin` — номер не нужен.
- **Ссылка для нового блогера.** На экране «Приглашения» кнопка
  «Ссылка для нового блогера»: заводит болванку без телефона и выдаёт
  одноразовую ссылку `/i/<токен>` — для тех, кого нет в таблице заказчика.
  Блогер открывает ссылку, вписывает свой номер, заполняет карточку.
- На бою (Vercel) `MASTER_KOD` и `ADMIN_LOGIN`/`ADMIN_PAROL` уже включены
  значениями по умолчанию; `ADMIN_TELEFONY` надо задать в настройках Vercel
  (Production), если нужен вход клиента по его номеру.
- ⚠️ **Перед тем как звать блогеров по-настоящему — очистить `MASTER_KOD`**
  и **сменить `ADMIN_PAROL`** (или очистить логин-вход). Пока они заданы,
  сервер пишет об этом в лог при каждом старте.

## Про скорость

Каталог и очередь модератора собирают карточки **пачкой**: три запроса на
всю страницу, а не три на каждую карточку. До 02.09.2026 страница каталога
стоила больше семидесяти запросов, а очередь модератора — почти тысячу;
отсюда и «лагает». Числовые поля отбора не дёргают сервер на каждую цифру:
запрос уходит, когда человек остановился, а прошлый отменяется.

  правкой этого блока, компоненты не трогаем.
