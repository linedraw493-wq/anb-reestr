# Реестр блогеров — код

Проект Ассоциации блогеров. Собирается по решениям 01–02.09.2026, они лежат
в `../voprosy-i-dyry.md`.

## Как устроено

**Одна служба.** На бою FastAPI сам отдаёт собранные страницы: один адрес,
один деплой, и не надо возиться с разрешениями между доменами. Пока сервера
нет — работает только `web/` с заглушкой.

| Папка | Что это | Готовность |
|---|---|---|
| `web/` | экраны: Vite + React 19 + TypeScript | шаг 1 — сделан |
| `api/` | сервер: FastAPI + asyncpg + PostgreSQL | шаг 2 — не начат |

Стек взят у «Лидера» (`C:/leader/`) — он в доме уже отработан.

## Два выключателя

Всё, что можно подменить, спрятано за одной строкой настройки.

| Выключатель | Где | Значения | Что решает |
|---|---|---|---|
| `VITE_API` | `web/.env` | `fake` · `live` | приглашения, карточки, заявки: заглушка или сервер |
| `VITE_OTP` | `web/.env` | `fake` · `live` | коды входа: `000000` или настоящий Telegram |

На бою (`web/.env.production`) стоит `VITE_API=fake`, `VITE_OTP=live` —
коды настоящие, всё остальное пока в браузере.

## Коды входа через Telegram

Временная замена SMS-оператору, слово владельца 02.09.2026.

Бот **@Kikokpklkbot**, все коды падают **в один чат владельца** — он их и
раздаёт. Иначе нельзя: бот Telegram не умеет писать первым ни по нику, ни
по номеру, только тому, кто сам ему написал.

Точка входа — `web/api/otp.js`, обычная функция Vercel на Node.

**Кода нигде не хранится.** Vercel запускает функцию заново на каждый
запрос, помнить между вызовами нечем. Поэтому код *выводится* из
случайного зерна и тайного ключа `OTP_SECRET`: при проверке сервер считает
его заново. В браузер уезжает только зерно с подписью — по нему код не
восстановить, не зная ключа. Подделать срок в билете тоже нельзя, подпись
не сойдётся.

**Чем платим:** счётчик попыток на сервере так не сделать — негде хранить.
Сейчас считает браузер (пять попыток), это честно слабее. Уйдёт на
Railway, когда появится база.

Настройки на Vercel: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CODE_CHAT_ID`,
`OTP_SECRET`. Их копии — в `app/.env`, вне git.

Если бота перезаведут или чат сменится:

```bash
python C:/bloggers/app/tools/podhvatit-chat.py --proba
```

## Окно регистрации — вариант А

Форма слева, справа карточка ровно в том виде, в каком её увидит
рекламодатель; меняется, пока человек печатает. На телефоне карточка
уезжает наверх, внизу липкая полоса «готово N из 7».

Что важно знать про этот экран:

- **Публикация после проверки.** Отправил → «Карточка на проверке» →
  модератор Ассоциации публикует. Слово владельца 02.09.2026.
- **Списки тематик, городов и районов — временные**, лежат одним файлом
  `web/src/lib/spravochniki.ts`. Заменить на настоящие — правка одного
  места, экраны не трогаются.
- **Чтение скрина поддельное.** Подставляет готовые цифры через полторы
  секунды. Настоящее чтение моделью в доме ещё не делалось — это
  отдельная работа.
- **Флаг достоверности:** цифры со скрина помечаются «со скрина», введённые
  руками — «со слов». Правка руками сбрасывает пометку на «со слов».
- Скрин не прочитался — регистрацию **не блокируем**, цифры вводятся
  руками с пометкой «со слов».

Пока стоит заглушка, **код всегда `000000`** — он же написан серой плашкой
внизу экрана. Плашка исчезнет сама, когда `VITE_API=live`.

Номера для проверки повторного входа: `8 701 765 4321` — есть в реестре,
любой другой — нет («такого номера в реестре нет», слово владельца).

## Границы

- Все ники и номера в `web/src/lib/fake.ts` — **вымышленные**. Настоящие
  телефоны 277 живых блогеров в репозиторий не попадают никогда.
- Наружу ничего не деплоится и не пушится без слова владельца.
- Стиль вынесен в переменные в начале `web/src/styles.css`. Пришлёт заказчик
  свой дизайн — переодеваем правкой этого блока, компоненты не трогаем.
