## 1. Полный user-flow — что и как сейчас работает

### 1.1. Гость (без входа)

- **`/` — каталог, он же главная.** Фильтры спрятаны за кнопкой: подписчики
  от/до, охват от, тематика, город (разложены по областям), район, язык,
  цена до. Поиск по нику. Четыре сортировки: по охвату, по подписчикам,
  дешевле, новые. Страницы по 24. Карта Казахстана — точки по городам, число
  в точке = сколько карточек в этом городе по текущему фильтру. Адрес
  сохраняет фильтры: скопировал ссылку — открыл, фильтры те же.
- **Клик по карточке → `/b/<id>` — публичная страница блогера.** Ник, фото,
  соцсети кликабельными иконками, подписчики и охват с пометкой «со слов» /
  «со скрина», город, тематики, ставка, счётчик просмотров. **Телефона нет
  нигде** — ни на странице, ни в ответе `/api/katalog`.

### 1.2. Блогер — регистрация (ядро спеки)

1. **`/i/<токен>` — «Это вы?».** Видит свой ник из заготовки. Номер: если
   он был в таблице заказчика — подставлен, можно поправить; если нет —
   вписывает сам. Галочка «согласен на обработку номера». → «Получить код».
2. **`/kod` — ввод кода, шесть цифр.**
   - Сейчас (демо-режим): подходит **`111111`** — любому. Настоящий код
     никуда не шлётся.
   - В боевом режиме: код уходит в Telegram-бота `@Kikokpklkbot`, все коды
     в один чат владельца, он раздаёт вручную. Живёт 5 минут, 5 попыток,
     повтор через минуту — считается в базе.
3. **Успех.** Заводится аккаунт блогера, ссылка гаснет (одноразовая),
   ставится cookie-сессия на 60 дней, в базу пишется строка согласия.
   Ведёт на `/kartochka` (или сразу в каталог, если карточка уже подавалась).
4. **`/kartochka` — карточка с живым предпросмотром.** Блоки:
   - **Кто вы:** фото (необязательно), ник, ссылки на профили — вставкой
     адреса, сеть определяется по домену.
   - **Цифры:** скрин статистики + подписчики и охват. Флаг достоверности:
     ввёл руками — «со слов», пришло со скрина — «со скрина».
   - **Про работу:** тематика (до 3), город, район (где есть), язык, ставка
     или «договорная».
   - Липкая полоса «готово N из 7».
5. **Скрин статистики.** Принимается, ужимается, кладётся в базу. **Чтение
   моделью отключено** — сервер честно отвечает «сохранили, цифры впишите
   сами», на форме и у модератора висит пометка «скоро».
6. **Отправка.** Модерация сейчас выключена → карточка сразу в каталоге.
   Включат модерацию → встаёт в очередь к модератору.
7. **Правка после публикации.** Ник, фото, ссылки, тематика, язык, ставка —
   меняются в каталоге сразу. Новые подписчики / охват / скрин у
   опубликованной карточки уходят отдельной правкой (в каталоге до
   одобрения висят прежние цифры; при выключенной модерации — тоже сразу).

### 1.3. Блогер — повторный вход

- **`/vhod`** → номер (любая запись: `+7…`, `8…`, `77…`, со скобками и
  пробелами — все ведут в один кабинет) → код → каталог. Номера нет в базе
  → «такого номера в реестре нет». Больше 10 попыток входа с адреса в
  минуту → «слишком часто».

### 1.4. Клиент (Ассоциация) и администратор

- **`/vhod` → «Вход для администратора»** → логин/пароль `admin` / `admin`.
  За ним один общий admin-кабинет без номера. Ведёт в `/moderator/priglasheniya`.
- Или: клиент по своему номеру (если вписан в `ADMIN_TELEFONY`) + код `111111`.
- Владелец — админ по номеру `+7 705 281 93 42` (задан в коде).

### 1.5. Админка / модератор

- **`/moderator` — проверка карточек.** Вкладки (на проверке / в каталоге /
  отклонённые / черновики) со счётчиками, страницами по 50. Открыл карточку
  → правка всех полей, пометка достоверности («со скрина — проверено» /
  «со слов»), «одобрить и опубликовать», «отклонить» с причиной (пишется
  текстом), «скрыть / вернуть», «завести карточку вручную», «удалить
  навсегда» (только у админа, у модератора — только «скрыть»). Журнал
  решений пишется.
- **`/moderator/priglasheniya`.** Список ссылок с состоянием (не открывал /
  открыл / зарегистрировался / просрочена / использована / нет ссылки),
  поиск по нику и телефону. Кнопки: «выпустить / новая ссылка» существующему,
  **«Ссылка для нового блогера»** (болванка без номера — для тех, кого нет
  в таблице), **«Резервный код»** (показывается на экране, живёт 5 минут, в
  Telegram НЕ уходит — админ диктует голосом).
- **`/moderator/spiski`.** Тематики, города, районы: добавить, переименовать,
  скрыть, слить два в один. У каждого пункта — число карточек.
- **`/moderator/svodka`.** Воронка: разослано ссылок → открыли → подтвердили
  номер → заполнили карточку → в каталоге. Плюс просмотры и «ждут долго».

### 1.6. Контакт «подборщик ↔ блогер» (K6)

По разбору 01.09 задумано: чат внутри сайта + уведомление в сайте (не push)
+ контакты прямо на карточке. **Не построено** — место в схеме есть
(таблица `uvedomleniya` заведена, но не используется). Спека относит это ко
2 этапу — сейчас это правильно не делать.

## 4. Что не работает, что отключено, где долги

### 4.1. Отключено сознательно

1. **Чтение скрина статистики моделью.** `/api/card/screenshot` намеренно
   всегда отвечает «не прочитал». Отчёт ИИ у модератора — заглушка с
   пометкой «пример / скоро». Причина: нет ключа `ANTHROPIC_API_KEY` и в
   доме ни разу не делался узел распознавания картинок. Ваше слово 02.09:
   «оставим на сайте как напоминалку».
2. **Проверка модератором при регистрации** (`MODERATSIYA=0`). Карточки
   идут в каталог без проверки. Очередь и все кнопки модератора работают —
   просто вкладка «на проверке» всегда пустая. Ваше слово 02.09.
3. **Настоящая доставка кодов.** Пока `MASTER_KOD=111111` — коды никуда не
   шлются, `111111` открывает любой кабинет. Демо-режим, чтобы клиент мог
   зайти без казахстанского SMS-оператора.

### 4.2. Не построено (за рамками недели 1)

4. Чат «подборщик ↔ блогер», уведомления внутри сайта (таблица
   `uvedomleniya` пустует), контакты на карточке — 2 этап.
5. Кнопка «удалить себя» у блогера; текст согласия и политики от юриста
   заказчика; инструкция для админа; передача доступов.
6. **Готовые причины отказа.** Шесть штук лежат в таблице `prichiny_otkaza`,
   к экрану модератора **не подключены** — модератор пишет причину руками.
7. **Загрузочные и пустые состояния.** Есть только в каталоге; на входе,
   карточке и в админке пока нет.

### 4.3. Мусор в коде (не ломает, но путает)

8. `app/web/src/lib/otp.ts` и `app/web/api/otp.js` — остаток от подхода

   FastAPI (`/api/auth/start`, `/api/auth/check`), а `/api/otp` на боевом
   сервере вообще нет. `otp.ts` используется лишь для подписи «Код отправлен
   в Telegram» и в заглушке. Стоит убрать.
9. `render.yaml` пустой, `Dockerfile` — под Render/Railway, не используются
   (бой на Vercel). Не мешают, но вводят в заблуждение.

### 4.4. Долги и риски

10. **Токен Telegram-бота светился в переписке 02.09** — до сих пор не
    перевыпущен. Дыра, через которую файл с токеном утекал (`/../../.env`),
    закрыта, но `/revoke` в `@BotFather` не сделан. Пока `MASTER_KOD` задан,
    бот в боевом входе не используется — но перевыпуск всё равно нужен.
